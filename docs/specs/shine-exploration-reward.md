## 0. 이 문서가 결정하는 것

[`docs/PROJECT.md`](../PROJECT.md)는 리워드 방식을 **"이후 결정"**으로 남겨 두었다.
이 스펙은 팀 결정을 대신하지 않는다. 개인 과제 범위에서 **하나의 가설을 시연하고 인터뷰로 확인하기 위한 실험용 규칙**을 정한다.

**검증 질문:** 주선자가 소개할 친구를 살펴보고 고민할 때, 작은 보상이 **참여할 재미**를 주는가, 아니면 오히려 **가볍고 어색하게("짜치게")** 느껴지는가?

이 문서의 금액(+10P), 상한 없음, 1P = 1원 가정은 **이번 실험용 값**이다. 실제 서비스의 금액·상한·사용처는 정하지 않는다.

## 1. 한 문장

**주선자가 싱글 친구 두 명을 골라 어울릴 것 같은 이유를 한 줄 적어 비공개 '짝 후보'로 저장하면, 처음 저장한 조합에 한해 체험용 +10P가 쌓인다.**

### 대상과 문제 상황

- **대상:** 싱글 친구를 여럿 알고 있는 **기혼 주선자**.
- **문제 상황:** 소개는 "누구와 누구를 이어 줄까"를 떠올리는 데서 시작한다. 그런데 이 고민은 눈에 보이는 결과가 없어, 앱을 열 이유가 되지 못한다. 기존 리워드 아이디어는 단계(추천사·연결·약속)를 넘을 때만 보상하므로, **소개가 시작되기 전의 탐색과 고민에는 아무 보상도 없다.**
- **피하고 싶은 것:** 프로필 클릭당 1원, 30초당 10원처럼 **반복 클릭이나 체류 시간에 보상**하는 방식. 고민하지 않아도 보상이 쌓이고, 토스·카카오페이의 적립 광고처럼 가볍게 느껴질 수 있다.
- **그래서 정한 방향:** 클릭이나 시간이 아니라, **두 사람을 비교하고 이유를 생각해야만 완성되는 행동**(짝 후보 메모)에 보상한다.

### 왜 이 기능인가 (WhyTree 경로)

```
좋은 사람을 만나 연애하기
└─ 상대를 만나 서로 알아가기
    └─ 새로운 만남의 기회
        └─ 기혼 주선자끼리 소개할 친구 찾기   ← 이 기능
```

- 탐색 리워드는 주선자가 **소개할 친구를 찾는 행동**을 늘리려는 수단(How)이다.
- 짝 후보 메모의 "이유 한 줄"은 이후 `상대를 판단할 신뢰 근거 > 지인 관계·소개 이유 확인`에서 쓸 **추천사의 초안**이 된다. 다만 이번 범위에서는 연결 기능을 만들지 않는다.
- 현재 WhyTree는 **싱글의 목표**를 중심으로 짜여 있고, "주선자가 앱을 계속 쓰는 이유"를 다루는 노드는 없다. 이 기능은 위 리프 노드의 How로 둔다.

## 2. 사용자 흐름

한 화면에서 끝난다. 지갑이나 별도 화면은 없다.

1. **화면을 연다.** 상단에 누적 포인트(예: `0P`)와 ⓘ 안내가 보인다.
2. **친구 목록을 훑는다.** 가상 싱글 친구 6명의 카드(이니셜 아바타, 이름, 나이, 직업, 지역, 관심사 2~3개, 한 줄 소개)를 본다. 프로필을 보거나 선택하는 것만으로는 포인트가 쌓이지 않는다.
3. **두 명을 고른다.** 두 명이 선택되면 이유 입력칸이 열린다. 세 번째를 고르려 하면 막는다.
4. **이유를 한 줄 적는다.** 앞뒤 공백을 제거한 길이가 10자 미만이면 저장 버튼이 꺼져 있고, "어울릴 것 같은 이유를 10자 이상 적어 주세요"라고 안내한다.
5. **짝 후보로 저장한다.**
   - **새 조합이면:** 짝 후보 목록에 추가되고, `+10P` 토스트가 잠깐 뜨며, 누적 포인트가 10 늘어난다.
   - **이미 저장한 조합이면**(선택 순서가 달라도): 기존 메모를 새 이유로 바꾸고, "메모를 수정했어요 (이미 포인트를 받은 조합이에요)"라고 안내한다. 포인트는 늘지 않는다.
6. **저장된 짝 후보를 본다.** 각 카드에는 두 사람, 이유, 그리고 아래 단계 리워드 안내가 꺼진 상태로 보인다.
   > 다음 단계: 추천사 작성 +100P · 연결 +50P · 약속 +50P
   > **컨셉 예시 · 이번 체험에서는 미동작**
7. **메모를 수정한다.** 카드에서 이유를 고칠 수 있다. 같은 10자 조건을 적용하고, 포인트는 늘지 않는다.
8. **체험 초기화.** 실수를 막기 위해 버튼을 두 번 누르면(첫 번째에 "한 번 더 누르면 모두 지워져요") 짝 후보와 누적 포인트가 모두 지워지고 1번 상태로 돌아간다.

### ⓘ 안내에 표시할 문구

- 1P = 1원으로 가정한 체험용 포인트이며, 실제 사용·환전은 불가합니다.
- 친구 정보는 모두 가상 데이터입니다.
- 짝 후보 메모는 나만 볼 수 있는 비공개 초안입니다. 저장해도 친구에게 알림이 가거나 소개가 시작되지 않습니다.
- 메모는 현재 브라우저에만 저장되며 외부로 전송되지 않습니다.

## 3. 보상 규칙 (실험용)

| 규칙 | 내용 |
|---|---|
| 보상 조건 | 친구 **서로 다른 2명** + 이유(앞뒤 공백 제거 후 **10자 이상**, 문장 안 띄어쓰기는 글자 수에 포함)로 짝 후보를 저장 |
| 보상량 | 새 조합 최초 저장 시 **+10P** (고정) |
| 조합 판정 | 순서와 무관하다. A-B와 B-A는 **같은 조합**이다 |
| 중복 | 같은 조합은 **한 번만** 보상한다. 수정·재저장에는 추가 보상이 없다 |
| 하루 상한 | 없음 (가상 친구 6명 → 최대 15개 조합, 최대 150P) |
| 보상 없는 행동 | 프로필 보기, 선택, 선택 해제, 체류 시간, 메모 수정 |
| 표시 | 적립 순간은 `+10P`로만 보여 준다. 원화 기준은 ⓘ 안내에서만 설명한다 |

**글자 수의 의미.** 10자는 최소 입력 조건일 뿐이다. 실제로 고민했는지는 앱이 판정하지 않고, 시연 후 인터뷰에서 확인한다.

### 데이터 (현재 브라우저 localStorage)

```
pairCandidate {
  pairKey:    string   // 두 친구 id를 정렬해 이은 값. 예: "f2|f5" → 순서 무관 판정
  friendIds:  [string, string]
  reason:     string   // 앞뒤 공백 제거 후 저장, 길이 ≥ 10
  rewarded:   true     // 최초 저장 시 지급 기록
  createdAt:  number
  updatedAt:  number
}
totalPoints: number    // = 보상받은 pairKey 수 × 10
```

- 같은 `pairKey`로 다시 저장하면 `reason`과 `updatedAt`만 바뀌고 `totalPoints`는 그대로다.
- 보상 판정(`pairKey` 생성, 이유 검증, 적립 여부)은 화면과 분리한 함수로 둔다. 그래야 규칙을 따로 확인할 수 있다.

## 5. 제외 범위

- **실제 돈 지급, 포인트 사용·환전**
- **실제 사용자 데이터, 로그인, 사용자별 접근 제어**: 가상 데이터만 쓴다
- **서버 저장, 외부 전송**: 메모는 현재 브라우저에만 저장한다
- **당사자 알림, 소개 시작**: 짝 후보 저장은 주선자 혼자 보는 비공개 초안이다
- **단계 리워드의 실제 동작**: 정적 안내만 보여 준다
- **클릭당·체류 시간당 보상, 점점 늘어나는 보상**
- **별도 지갑 화면**
- **앱 안의 반응 설문**: 재미와 어색함은 시연 후 인터뷰로 확인한다
- **반복 문자("ㅋㅋㅋㅋ…") 같은 저품질 입력 차단**: 그런 입력이 나오는지도 관찰 결과로 본다

### AI 모델 미사용

이 기능은 **AI 모델을 사용하지 않는다.** 짝 후보 추천, 이유 자동 작성, 이유 품질 판정을 모두 하지 않는다.
조합 판정과 보상은 정해진 규칙(정렬된 `pairKey`, 글자 수 ≥ 10, 최초 저장 여부)으로만 계산한다.
고민하는 주체가 주선자 본인이어야 검증 질문이 성립하기 때문이다.

## 7. 시연 후 인터뷰 (측정)

앱 안에서는 수집하지 않는다. 시연 후 물어볼 것은 다음과 같다.

| 질문 | 확인하려는 것 |
|---|---|
| `+10P`가 떴을 때 어떤 느낌이었나요? (재미있다 / 별 느낌 없다 / 가볍고 어색하다) | 검증 질문의 직접 답 |
| 포인트가 없었어도 짝 후보를 저장했을까요? | 보상이 행동의 이유였는지 |
| 이유를 적을 때 실제로 두 사람을 비교했나요, 10자를 채우려고 적었나요? | 10자 조건이 고민을 유도했는지 |
| 단계 리워드 안내(+100P 등)를 보고 다음 단계를 해 보고 싶었나요? | 탐색 리워드와 단계 리워드의 연결 |

같이 기록할 것: 저장한 짝 후보 수 / 가능한 조합 15개, 이유의 평균 글자 수, 수정 횟수. **분자와 분모를 함께 적는다.** 표본이 작으면 비율만으로는 아무 말도 할 수 없다.
