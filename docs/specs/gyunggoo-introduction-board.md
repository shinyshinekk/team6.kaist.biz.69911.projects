# TTU — 한 건을 끝내는 소개 보드

v1.2 / 2026-10-28 / 사용자 문제 선택·자율 작성 위임에 따른 명세.

독립 검수 후 변경(v1.2): 역할 전환·다시 읽기의 늦은 응답은 최신 화면을 덮지 못한다. 응답을 읽는 동안 이전 역할의 소개는 숨기고 변경 버튼을 막는다. 저장 중에는 역할·새로 읽기·초기화·생성을 잠근다. 생성 요청의 409 충돌 후에는 최신 상태를 다시 읽어 다음 시도가 같은 오래된 version을 쓰지 않게 한다. 유효 JSON이어도 null 이벤트·잘못된 식별자/시각·배열 receipts·충돌하는 nextId 등 잘못된 저장 데이터는 열기 단계에서 거부하고 파일을 보존한다. PRD §6.1의 검토 거절을 반영해 주선자도 검토 단계에서 소개를 종료할 수 있다. 거절자/이유는 공유하지 않는다. 소개 종료는 기록의 물리 삭제가 아니며 복원 기능도 아니다. 가역적 보류/해제와 테스트 자료 전체 초기화만 제공한다. 이 변경을 먼저 명세에 기록하고 코드와 회귀 테스트에 반영한다.

변경 기록: v1.1은 화면 검증에서 발견한 다음 행동 안내의 어색한 조사를 명시적인 문장으로 고친다. WhyTree 미리보기는 CSP에 맞는 별도 CSS를 쓰고, 함께 제공하는 PPTX/PDF를 명시적 파일 목록으로만 읽을 수 있게 한다. 단계·동의·집계 규칙은 v1.0을 유지한다. 이 변경을 먼저 기록한 뒤 코드에 반영한다.

## 누구의 어떤 문제인가

기혼 주선자가 여러 소개를 함께 진행할 때 누구의 확인을 기다리는지, 지금 무엇을 해야 하는지, 실제로 연결이 끝났는지를 기억하고 메신저를 뒤지는 수고가 크다. 한 화면에서 단계와 다음 행동 한 가지를 보여주고, 단계별 독립 응답에 따라 진행을 기록한다. 후보를 자동으로 찾아주거나 관계 성사를 보장하는 기능은 아니다.

WhyTree: `좋은 소개를 끝까지 이어주기 > 주선자의 조율 부담 줄이기 > 소개 진행 상태 한곳에 모으기`. 다른 두 가지인 선택권과 실제 연결 확인은 보드의 상태 규칙에 반영한다.

## 정한 작은 범위와 전제

이미 서로 협력하고 후보의 최소 요약을 공유할 동의를 받은 주선자 A/B와 합성 후보 코드만 사용한다. 실제 회원 가입·관계 승인·협력 링크·프로필 데이터는 이번 개인 기능 밖이다. 테스트 actor 선택은 실제 인증이 아니다. 서버는 해당 합성 actor의 참여 관계·역할·현재 단계를 검사하지만 실서비스 신원 인증·기혼 검증을 했다고 주장하지 않는다. 실명·사진·연락처·자유 메모 입력 필드를 두지 않는다.

## 사용 순서

1. 주선자 A로 보드를 연다. 자신의 소개 건만 단계/다음 행동과 함께 보인다. 모든 숫자와 기록은 합성 데모다.
2. 승인된 합성 후보 쌍으로 소개 건을 하나 만든다. 같은 쌍의 진행 중 소개를 중복 만들 수 없다.
3. 참여 주선자 A/B가 각자 검토한다. 검토 단계에서 한쪽이 거절하면 종료한다. 양쪽 검토 뒤에만 싱글 소개 동의 단계로 간다.
4. 합성 싱글 역할에서 각각 소개 수락/거절을 기록한다. 양쪽 수락 후에도 정보 공유 승인은 별도다. 주선자가 싱글 응답을 대신 클릭할 수 없다.
5. 싱글 양쪽이 각각 공유를 승인해야 연결 확인 단계가 열린다. 연락은 발송하지 않는다. 두 주선자가 각자 합성 시나리오의 실제 연결 확인을 기록한 뒤에만 소개 완료로 센다.
6. 소개 완료 후 만남 확인/아직 만나지 않음/미확인을 기록해 후속 상태를 남긴다. 소개 연결과 실제 만남은 서로 다른 기록이다.
7. 보류는 진행을 멈추며 기존 기록을 지우지 않는다. 참여자 철회·거절은 소개를 종료한다. 공유 화면에는 누가 거절했는지나 이유를 노출하지 않는다. 종료 뒤 진행 버튼은 작동하지 않는다.
8. 새로고침/서버 재시작 뒤에도 로컬 데이터가 남는다. 데모 초기화는 합성 초기 기록으로 돌린다.

## 상태와 다음 행동

보드 상태는 기록에서 계산한다. 주선자 검토 → 싱글 소개 동의 → 별도 정보 공유 동의 → 양쪽 주선자 연결 확인 → 후속 확인/정리. 보류·종료가 진행보다 우선한다. 한쪽 수락, 공유 승인, 주선자 연결 확인만으로 소개 완료를 만들지 않는다. 다음 행동은 현재 actor가 할 수 있는 행동 또는 기다리는 절차를 한 문장으로 표시한다. 오래 기다렸다는 이유로 자동 승인·성사·재촉 알림을 만들지 않는다.

## 손으로 하는 체크 3개

1. **정상 한 바퀴:** 합성 소개 생성 → 주선자 A/B 각각 검토 → 싱글 둘 각각 수락 → 각자 별도 공유 승인 → 주선자 A/B 각각 연결 확인 → 후속 상태 기록. 중간 한 명만 응답했을 때 다음 단계/완료가 열리지 않는지 확인한다.
2. **경계/비공개:** 무관한 M-C는 건을 볼 수 없다. 주선자 역할로 싱글 동의를 바꿀 수 없다. 참여 싱글이 거절/철회하면 종료되고 공유 보드에 거절자·이유가 표시되지 않는다. 보류·종료 후 진행이 막히는지 본다.
3. **지속/실패:** 새로고침·서버 재시작 후 기록 유지, 중복 버튼/오래된 version 요청이 상태를 두 번 올리지 않는지, 저장 실패가 성공으로 보이지 않는지 확인한다. 마지막에 합성 데모를 초기화한다.

검사 방향과 AI 실행 위임은 사용자가 정했다. 아래 검사 기록에서는 AI의 실제 화면 조작과 자동 검사를 구분한다. 사용자가 화면을 직접 클릭한 것으로 바꾸어 쓰지 않으며, 결과에 대한 사용자 판정은 실제 응답을 받은 뒤 기록한다.

## 설계 검토 성격

실제 사용자 발언은 제품 TTU, 최신 주선자 문제, 추가 세부 질문 대신 자율 작성 위임이다. 이 명세의 상태·범위·예외 처리는 위임 아래 내린 설계다. Matt Pocock의 설치된 grill-me 진입점과 grilling 본체 총 4개 파일이 공식 고정 커밋 49dd158d1076134a641b33efb035946536778336과 정확히 일치함을 후속 검증했다. Codex에서 두 스킬을 로드하고 실제 발언/위임을 입력으로 설계 트리·권고·반례 검토를 수행했다. 실제로 하지 않은 사용자 문답을 기록하지 않는다.

2026-10-28 마지막 공유 이해 확인 완료. “TTU 주선자가 여러 소개의 진행 단계와 다음 할 일을 한곳에서 보고, 당사자 동의와 연결 여부까지 관리하는 보드.”라는 범위가 원하는 방향인지 묻자 사용자가 “ㅇㅇ 그래 맞다”라고 답했다. 이 실제 응답으로 위임 방식의 grill-me 설계 검토에서 남아 있던 마지막 frontier를 닫았다. 같은 확인을 다시 요청하지 않는다. 세부 문항마다 본인이 답한 연속 면담이나 Claude marketplace 플러그인 UI 설치/슬래시 호출을 했다고 주장하지 않는다. 이후 본인 파일 대조 확인과 검사의 수행 주체·검증 범위는 아래 2026-10-29 보완 기록에서 구분한다.

## 검증 기록 보완 — 2026-10-29

동작 명세 v1.2와 P0/P1/P2, 코드·슬라이드의 노드와 연결은 유지한다. 이번 보완은 확인 사실과 검사 수행 주체를 문서에 반영하는 변경이다. 이 변경 기록을 먼저 저장한 뒤 아래 확인 상태와 WhyTree·실행 안내의 검사 기록을 갱신한다.

사용자는 제시된 PPTX/MD의 10개 노드·9개 연결을 확인했다고 답했고 수정 요청은 없었다. 이후 검사 방향을 정하고 AI에 실행·결과 반영을 지시했다. AI의 기존 실제 Chrome 검사와 자동 검사를 구분해 기록하며, 새 UI 검사는 정책 중단으로 실행하지 못한 상태다. 사용자가 결과를 검토해 내린 판정은 실제 응답을 받은 뒤 기록한다. 사용자가 화면을 직접 클릭했다고 쓰지 않는다. AI 실행 방식이 과제의 ‘본인이 직접 검사’ 요건으로 인정되는지는 확인되지 않았다.
