## 1. 누구를 위한 기능이며 어떤 순간에 필요한가

- **사용자:** 성인 싱글 S. 가상 시연에서는 한 S가 기혼 주선자 M1과 M2에 독립적으로 연결돼 있다.
- **문제 순간:** 주선자가 먼저 소개하기를 기다리는 대신, S가 원하는 성향·취미·대화 스타일을 **선택한 주선자 단 한 명에게만** 요청하고 진행 상태를 확인하고 싶다. 공개 프로필을 넓히거나 다른 후보를 무단 탐색할 필요가 없어야 한다.
- **제품 가치:** 싱글에게 능동적인 행동을, 주선자에게 구체적인 다음 행동을 제공한다. 실제 소개·AI 매칭이 자동 수행된다는 뜻이 아니다.
- **SLC 최소 완결:** `싱글 입력·수신자 확인 → 지정 주선자 수신함 접수 → 검토 시작 → 종료` 또는 `철회/만료/연결 해제`로 요청 1건을 완결한다.

## 3. 팀 PRD에서 계승한 제약(개인 정책보다 상위)

- D13: 싱글은 승인한 기혼 주선자 여러 명과 별도로 연결·해제할 수 있다.
- F18: 요청은 선택된 활성 주선자 **1명**만 수신한다. 상대 싱글/다른 주선자에게 자동 전송하지 않는다.
- D17/F20: 싱글이 L0 비공개, 발견 카드 0명이어도 요청할 수 있고, 요청은 공개 단계·소개 수락·연락처 공유 동의를 바꾸지 않는다.
- AI가 요청을 받거나 사람을 평가·매칭하지 않는다. 주선자가 판단하고 양측 싱글의 수락·최종 공개 동의는 **별도 소개 프로세스**에 속한다.
- `preference_nudge_submitted` 이벤트만 증가. `proposal_created`, `mutually_accepted`, `introduced`와 동치가 아니다.

## 5. 순서대로 수행할 기능

### 5.1 싱글
1. L0 비공개·후보 0명 안내를 본다. M1 또는 M2 중 현재 연결된 주선자를 선택한다.
2. 키워드 1~3개를 선택하고, 원한다면 120자 이내 설명을 입력한다.
3. 누가 받는지/무엇을 받는지/다른 주선자는 못 받는지 사전 확인 후 체크한다.
4. 유효성·24시간 제한·진행 중 1건 제한을 통과하면 `received` 요청 ID가 생성된다.
5. 검토 중인 요청도 철회할 수 있다. 철회하면 해당 요청 원문이 활성 영역에서 제거되고 상태 기록만 보인다.
6. 주선자 연결을 해제하면 그 주선자의 활성 요청은 `closed/link_removed`로 종료된다. 다른 연결은 보존한다.

### 5.2 주선자
1. 가상 M1/M2 수신함을 선택한다. 해당 M의 활성 연결과 수신 요청만 보인다.
2. 새 요청을 `검토 시작`으로 전환한다. **첫 검토 시작 시각부터 7일**로 만료 기준이 한 번 재설정된다.
3. `향후 검토 가능` 또는 `이번 요청 진행 어려움` 중 하나로 종료한다. 내부 상태 코드는 남지만 싱글에게는 **‘종료’**만 보인다.
4. 검토 결과가 나왔더라도 소개 제안/상대 수락/연락처 공개는 생성되지 않는다.

### 5.3 시스템/시연 시간
- 접수 후 7일간 아무 동작이 없으면 만료, 검토 시작 후에는 그 시점부터 7일간 진전이 없으면 만료.
- 브라우저 시연용 가상 시간은 버튼으로 +1시간/+1일/+6일/+7일 이동 가능. 서버 백그라운드 잡을 구현한 것은 아니다.
- 새로고침하면 모든 요청·감사 기록이 초기화된다. 외부 서버, 브라우저 로컬 저장소에 저장하지 않는다.

## 6. 상태 및 데이터 구조

### 상태 전이

```text
received --[지정 주선자 첫 검토]--> reviewing --[결과 선택]--> closed/{possible_later|cannot_proceed}
received/reviewing --[본인 철회]--> closed/withdrawn_by_single
received/reviewing --[해당 관계 해제]--> closed/link_removed
received/reviewing --[7일 무진전]--> closed/expired_inactive
```

- 이미 종료된 ID는 다시 처리할 수 없다. 새 요청은 새 ID가 필요하다.
- `received`부터 7일, 최초 `reviewing` 전환 시 한 차례 7일 재설정. 반복 검토로 추가 연장하지 않는다.
- 싱글 공개 라벨: `received=접수됨`, `reviewing=검토 중`, 주선자 종료 결과 `closed/*=종료`, 자기 철회/만료/해제는 각각 설명 추가.

### 논리 구조(가상 시뮬레이션, 실서비스 DB 아님)

진행 요청: `id, to, tags[], description, status, submittedAt, firstReviewedAt, expiresAt`.
종료 기록(주선자별 보관함): `id, submittedAt, closedAt, status`만 유지.
한 조합의 최근 제출 시각은 `lastSubmitted[M]`로 별도 보유하여 24시간 쿨다운을 검증한다. 싱글 공개 설정 `visibility=L0`, 발견 후보 `cardsAvailable=0`은 고정이다.

## 8. 오류/AI 실패 처리

- 입력값이 유효하지 않으면 원인과 수정 방법을 안내하고 **요청/수신함을 변경하지 않는다**.
- 수신자 관계가 없거나 다른 수신함에서 처리하려 하면 거절한다. **이는 JavaScript의 모의 규칙이며 실제 서버 인증/인가 대체가 아니다.**
- 가상 시간 경과로 이미 만료된 요청은 처리할 수 없다. 종료 건 원문은 삭제되고 상태 최소 기록만 남는다.
- **실행 AI 모델 없음**. LLM을 통한 필드 생성·권한 부여·요청 경로 결정을 수행하지 않으므로 AI 실패에도 현재 규칙 기반 시연은 변하지 않는다.
- 실제 외부 전송·DB 오류·네트워크 장애 복구는 **테스트하지 않았으며 구현 범위 아님**.
