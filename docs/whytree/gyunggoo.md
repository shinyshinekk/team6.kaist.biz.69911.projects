# TTU WhyTree — 강경구

현재 방향: 기혼 주선자가 여러 소개를 관리하고 사람을 이어주는 수고를 줄인다. 사용자 최신 문제 선택과 세부 작성 위임을 반영한 개인 초안이다. 아래 문구·계층은 그 위임에 따른 설계이며 사용자가 각 노드에 직접 답한 문답 기록이 아니다.

2026-10-28 공유 이해 확인 완료: “TTU 주선자가 여러 소개의 진행 단계와 다음 할 일을 한곳에서 보고, 당사자 동의와 연결 여부까지 관리하는 보드.”라는 범위에 사용자가 “ㅇㅇ 그래 맞다”라고 답했다. 이는 기능 방향의 확인이며 각 노드 문구를 본인이 직접 대조·교정했다는 뜻은 아니다. 같은 방향 확인을 다시 요청하지 않는다.

```text
좋은 소개를 끝까지 이어주기
  주선자의 조율 부담 줄이기
    소개 진행 상태 한곳에 모으기
    지금 할 일 하나 보여주기
  당사자의 선택권 지키기
    소개 수락과 정보 공유 동의 나누기
  연결 결과를 놓치지 않기
    양쪽 주선자의 실제 연결 확인받기
      연결 확인된 소개만 완료로 세기
    후속 확인과 다음 행동 남기기
```

씨앗 5개: 진행 상태 모으기, 할 일 하나, 수락/공유 동의 분리, 실제 연결 확인, 후속 확인. 템플릿에서 주황색으로 표시한다. 사용자 작성 위임에 따라 고른 제품 활동이며 실제 인터뷰로 사용자가 각각 선택했다고 쓰지 않는다.

Why Up: 여러 소개의 진행을 모으는 이유는 조율 수고와 누락을 줄여 한 건의 소개가 끝까지 이어지게 하기 위해서다. How Down: 상태를 모으는 것 외에도 다음 행동 하나를 보여주고, 동의와 실제 연결을 구분하고, 후속 확인을 남기는 방법이 있다.

선택 기능: [한 건을 끝내는 소개 보드](../specs/gyunggoo-introduction-board.md). 근거는 TTU PRD v0.5 §3 W2/W3, §4 P-A, §6.1/6.3, F04/F07/F08/F10, §8.1~8.4다. 같은 팀의 후속 제품 문서지만 SAI의 개명이라고만 단정하지 않는다. SAI의 12명 집계 기준을 적용하지 않는다.

편집 가능한 PPTX와 검토 PDF는 `prototypes/gyunggoo/`에 함께 둔다. 개인 진로 대화 원문·접근 URL·개인정보는 제출 후보에 포함하지 않는다. agent의 대조와 본인 직접 대조를 구분한다.

본인 마지막 확인: [x] 노드 문구/연결이 내 생각에 맞는지 읽기 [x] PPTX와 이 텍스트 대조.

2026-10-29 제시된 10개 노드·9개 연결과 PPTX/MD 링크를 보고 사용자가 직접 확인했다고 답했다. 수정 요청은 없었다. AI의 실제 파일 재대조도 문구·부모 관계 차이 0개였다. 별도로 놀랐던 특정 노드나 새로운 경험을 사용자의 답으로 만들어 넣지 않는다. 이 확인은 파일 대조에 관한 것이며 화면 클릭 검사 완료를 뜻하지 않는다.
